# client-app

The Cadenza mobile app. Expo / React Native with expo-router for navigation, nativewind for
styling, SWR for data. Talks to Apple Music through a local native module and to `backend-api`
over HTTP.

## Files

| path | role |
| --- | --- |
| `src/app/` | expo-router routes. See [src/app/README.md](src/app/README.md). |
| `src/lib/` | Data layer and providers. See [src/lib/README.md](src/lib/README.md). |
| `src/features/` | Self-contained features. Today: [query-builder](src/features/query-builder/README.md). |
| `src/components/` | UI. See [src/components/README.md](src/components/README.md). |
| `modules/apple-musickit/` | Local native Expo module. See [modules/apple-musickit/README.md](modules/apple-musickit/README.md). |
| `app.json`, `eas.json` | Expo app config and build profiles. |
| `tailwind.config.js`, `global.css`, `components.json` | nativewind / tailwind and shadcn-style generator config. |
| `metro.config.js`, `babel.config.js`, `tsconfig.json` | Bundler, transform, and path aliases. |
| `ios/` | Generated by prebuild. Not hand edited. |

## Path aliases

Defined in `tsconfig.json`:

- `@/*` -> `client-app/src/*`
- `@apple-musickit` -> `client-app/modules/apple-musickit/index`

Use them. Relative `../../` imports across directories are the exception, not the rule.

## Environment

`client-app/.env`, gitignored. Expo inlines `EXPO_PUBLIC_*` at bundle time.

| var | notes |
| --- | --- |
| `EXPO_PUBLIC_BACKEND_API_URL` | Backend base url, e.g. `http://192.168.1.25:3000`. Read only by `src/lib/tag-generation.ts`. See the gotcha below. |
| `EXPO_PUBLIC_MUSICKIT_DEVELOPER_TOKEN` | Apple Music developer token. Required for real playback. |
| `EXPO_PUBLIC_MOCK_MUSICKIT` | Set to `1` for fixture data and no audio, so you can work without an Apple Music subscription. |

Changing any of these needs a Metro restart with `--clear`. A hot reload will not pick up a new
value, because they are inlined into the bundle.

## Scripts

```sh
npm run ios        # expo run:ios
npm run android    # expo run:android
npm start          # metro only
npm run lint       # expo lint
npx tsc --noEmit   # typecheck
```

## Connects to

- `backend-api` at whatever base url `src/lib/backend.ts` resolves to, with a Supabase JWT on
  every request.
- Supabase directly for auth, from `src/lib/supabase.ts`.
- Apple Music through `@apple-musickit`.

## Gotchas

- **Two different base urls.** `src/lib/backend.ts` hardcodes `http://localhost:3000` and is what
  every SWR hook and the query builder use. `src/lib/tag-generation.ts` has its own resolver that
  reads `EXPO_PUBLIC_BACKEND_API_URL` and falls back to the Expo host. On a physical device
  `localhost` is the phone, not your Mac, so the hardcoded one cannot work there. Details in
  [src/lib/README.md](src/lib/README.md).
- The backend defaults to binding loopback. To reach it from a phone, set `BIND_ADDR=0.0.0.0:3000`
  in `backend-api/.env`.
- `ios/` is prebuild output. Native changes go in `app.json` plugins or `modules/`, then rebuild.
- `nanoid` is imported by `src/features/query-builder/QueryUtils.ts` but is not in
  `package.json`. It resolves today only as a transitive dependency.
