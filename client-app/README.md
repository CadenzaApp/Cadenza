# client-app

The Cadenza mobile app. Expo / React Native with expo-router for navigation, nativewind for
styling, SWR for data. Talks to Apple Music through a local native module and to `backend-api`
over HTTP.

## Path aliases

Defined in `tsconfig.json`:

- `@/*` -> `client-app/src/*`
- `@apple-musickit` -> `client-app/modules/apple-musickit/index`
- `@image-color` -> `client-app/modules/image-color/index`

Use them. Relative `../../` imports across directories are the exception, not the rule.

## Data fetching

Nothing in the UI calls `fetch` directly. Components call a hook out of `src/lib/routes/`, which
is a one to one mirror of the axum routers in `backend-api/src/routes/`. Those hooks are built on
the wrappers in `src/lib/api-actions.ts`:

- `useAPIData` for cached GETs that run on mount.
- `useAPIPostData` for cached reads whose request body is part of the key.
- `useAPIPostDataBatched` for cached reads whose list payload must be split into batches.
- `useAPIFetch` for GETs that only run when the user asks.
- `useAPIMutation` for writes, with an explicit list of caches to invalidate.

There is no automatic invalidation. A mutation that lists nothing leaves stale data on screen.
The rules, the cache key shape, and how to add an endpoint are in
[src/lib/README.md](src/lib/README.md).

## Environment

`client-app/.env`, gitignored. Expo inlines `EXPO_PUBLIC_*` at bundle time.

| var                                    | notes                                                                                                                    |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `EXPO_PUBLIC_BACKEND_API_URL`          | Backend base URL used by `src/lib/backend.ts`, including an HTTPS deployment URL. Falls back to `http://localhost:3000`. |
| `EXPO_PUBLIC_MUSICKIT_DEVELOPER_TOKEN` | Apple Music developer token. Required for real playback.                                                                 |
| `EXPO_PUBLIC_MOCK_MUSICKIT`            | Set to `1` for fixture data and no audio, so you can work without an Apple Music subscription.                           |
| `APPLE_BUNDLE_ID`                      | Overrides `ios.bundleIdentifier` in `app.config.js`. Defaults to `com.cadenza.cs4000`.                                   |
| `APPLE_TEAM_ID`                        | Overrides `ios.appleTeamId`. Leave unset and Xcode resolves the team from the signed-in account on first GUI build.      |

Changing any `EXPO_PUBLIC_*` value needs a Metro restart with `--clear`. A hot reload will not
pick up a new value, because they are inlined into the bundle. `APPLE_BUNDLE_ID` and
`APPLE_TEAM_ID` are read at config evaluation time, so changing either needs a fresh prebuild.

## Connects to

- `backend-api` at whatever base url `src/lib/backend.ts` resolves to, with a Supabase JWT on
  every request.
- Supabase directly for auth, from `src/lib/supabase.ts`.
- Apple Music through `@apple-musickit`.

## Gotchas

- Use Node 26 (`nvm use` reads `.nvmrc`). SDK 58 / React Native 0.88 do not support Node 25.
- Expo SDK 58 uses `expo-glass-effect` 58.0.5+, including fixes for missing glass after
  opacity transitions and view recycling. Native dependency updates require a full dev-client
  rebuild. The upstream JSI package includes our former cache and Swift-interface fixes.
- `tsconfig.json` explicitly selects React Native's legacy type API while existing component
  libraries migrate to the strict API. TypeScript 6 loads Node and React types explicitly.
- `src/lib/backend.ts` reads `EXPO_PUBLIC_BACKEND_API_URL` for the API hooks and query builder.
  On a physical device the localhost fallback is the phone, so set a reachable LAN or HTTPS
  deployment URL before bundling. See [src/lib/README.md](src/lib/README.md).
- The backend defaults to binding loopback. To reach it from a phone, set `BIND_ADDR=0.0.0.0:3000`
  in `backend-api/.env`.
- `ios/` is prebuild output. Native changes go in `app.config.js` plugins or `modules/`, then
  rebuild. `expo-sqlite`, which backs the library sync's local record, is one of those
  plugins, so a checkout that predates it needs a dev client rebuild rather than a metro
  restart.
- `plugins/with-ios-build-fixes.js` is a local config plugin. It patches the generated iOS project
  during prebuild for signing and script sandboxing. SDK 58 supplies scene lifecycle support.
- The primary navigation uses Expo Router native tabs from `expo-router/native-tabs`.
- The [media-player guide](src/components/custom/media-player/README.md) covers native scroll
  docking, floating gestures, and bottom controls. The screens dependency patch requires
  `npx pod-install` followed by an iOS rebuild. The patch only disables native accessory
  insertion/removal animations; it adds no native props.
- Routine client validation is `npm test`, `npm run lint`, and a lightweight TypeScript check.
  Do not run `expo export`, native builds, simulators, or emulators unless the user asks or the
  change specifically requires them.
- App-owned glass controls still need `expo-blur` and `expo-glass-effect`, both native. If you
  pulled those dependencies without rebuilding, use `npm run ios` rather than `npm start`.
- Song-row tag rails use `@react-native-masked-view/masked-view` so their trailing edge fades to
  transparency over artwork-tinted detail screens. It is a direct dependency even though Expo's
  navigation tree also brings it in transitively.
